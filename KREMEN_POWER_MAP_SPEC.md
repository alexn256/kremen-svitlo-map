# Карта отключений света — Кременчук

## Контекст

Телеграм-бот "Svitlo Kremen Bot" (отдельный проект, см. `mazambik_parser_bot`) в
реальном времени знает статус 12 подочередей Кременчука (1.1–6.2): включена,
выключена, или идёт переключение — он получает это с сайта poe.pl.ua.

Есть справочник "адрес → подочередь" (PDF-график Полтаваобленерго), из которого
вручную готовится список домов Кременчука с привязкой к конкретной подочереди.
Важно: на одной и той же улице соседние дома могут относиться к *разным*
подочередям — это подтверждено вручную, не баг исходных данных.

Цель: отдельный сайт с картой Кременчука, на которой каждый дом из списка
окрашен в цвет своей текущей подочереди (зелёный — есть свет, красный — нет,
жёлтый — переключение), и эта раскраска обновляется вслед за live-статусом
бота.

**Это отдельный проект**, не часть репозитория бота. Парсинг исходного PDF и
подготовка списка адресов делается вручную/отдельно и в это ТЗ не входит —
сюда входит всё начиная с готового списка адресов.

## Объём (v1)

- Только город Кременчук (не вся область). Если схема окажется рабочей,
  дальше её масштабируют на остальную область — архитектура не должна этому
  мешать, но ничего сверх Кременчука сейчас не реализуется.
- Точки — по каждому дому (не по улицам целиком). Это осознанный выбор:
  детализация важна, потому что соседние дома могут быть в разных очередях.

## Входные данные

Список адресов Кременчука с привязкой к подочереди. Точный формат уточняется
отдельно (может быть txt/JSON/CSV — автор проекта ещё дорабатывает черновик
вручную). Ожидаемая логическая структура одной записи:

```
{ "street": "вул. Жовтнева", "house": "12", "queue": "1.1" }
```

Диапазоны домов ("3-209") в исходнике уже должны быть развёрнуты в отдельные
записи на этапе подготовки списка — геокодер работает с готовыми
домами, не с диапазонами.

## Пайплайн геокодинга (разовый, офлайн)

- Node.js-скрипт в `scripts/geocode.ts` (или .js), не часть рантайма сайта.
- Вход: файл со списком адресов (формат — см. выше, адаптировать под
  фактический файл, когда он появится).
- Геокодер: Google Geocoding API (нужен API-ключ с привязанным биллингом —
  заводит владелец проекта). Запрос вида
  `"{street}, {house}, Кременчук, Полтавська область, Україна"`.
- Кэшировать результат по адресу (не геокодить повторно при перезапуске
  скрипта — хранить промежуточный кэш `geocode-cache.json`, ключ — исходная
  адресная строка).
- Сохранять `precision` из ответа Google (`ROOFTOP` / `RANGE_INTERPOLATED` /
  `GEOMETRIC_CENTER` / `APPROXIMATE`) — пригодится для UI (например, показывать
  неточные точки чуть иначе).
- Выход: статический `public/houses.geojson`, формат GeoJSON
  `FeatureCollection` из `Point`-фич:

```json
{
  "type": "Feature",
  "geometry": { "type": "Point", "coordinates": [lng, lat] },
  "properties": {
    "address": "вул. Жовтнева, 12",
    "queue": "1.1",
    "precision": "ROOFTOP"
  }
}
```

- Адреса, которые Google не смог геокодить — не ронять весь прогон, собирать
  в отдельный `geocode-failures.json` для ручной проверки.

## Контракт live-статуса (отдаёт бот, не этот проект)

Бот должен будет публиковать публичный read-only эндпоинт (реализуется позже,
в проекте бота, не здесь):

```
GET https://<bot-host>/status.json
Access-Control-Allow-Origin: *

{
  "updated_at": "23.11.2026 14:32",
  "queues": {
    "1.1": "on",      // "on" | "off" | "switching"
    "1.2": "off",
    ...
    "6.2": "on"
  }
}
```

Сайт карты поллит этот URL каждые 30–60 секунд и перекрашивает точки без
перезагрузки страницы. Если эндпоинт недоступен — последний известный статус
остаётся на карте, точки не должны пропадать/сереть молча; стоит показать
маленький индикатор "данные устарели" с таймстампом последнего успешного
обновления.

## Технологии

| Слой | Выбор | Почему |
|---|---|---|
| Сборка | Vite + TypeScript | Лёгкий, быстрый dev-сервер, без лишнего фреймворка |
| Карта | Leaflet | Бесплатно, без API-ключа для показа, зрелая экосистема |
| Кластеризация | Leaflet.markercluster | Обязательно — несколько тысяч точек по домам нечитаемы без неё при отдалении |
| Тайлы | OpenStreetMap (по умолчанию) | Бесплатно для низкого трафика; если вырастет — перейти на бесплатный тир MapTiler/Stadia Maps (нужен будет API-ключ) |
| Геокодинг (разовый) | Google Geocoding API | Точнее, чем бесплатный Nominatim, для адресов уровня дома по Украине |
| Хостинг | Любой статический (Netlify / Vercel / Cloudflare Pages / GitHub Pages) | Сайт — чистая статика + fetch, бэкенд не нужен |

Путь роста (не делать сейчас, просто не архитектурить в тупик): при масштабировании
на всю область и десятках тысяч точек — рассмотреть **MapLibre GL**
(встроенная кластеризация через GeoJSON source, быстрее на больших объёмах).

## Цветовая схема

Совпадает с тем, что бот уже рисует на своих картинках графика — визуальная
согласованность между ботом и картой:

| Статус | RGB | HEX |
|---|---|---|
| Є світло (on) | 123, 198, 126 | `#7BC67E` |
| Немає світла (off) | 217, 83, 79 | `#D9534F` |
| Перемикання (switching) | 245, 194, 66 | `#F5C242` |

## UI-требования

- Попап по клику/тапу на точку: адрес, номер подочереди, текущий статус,
  время последнего обновления статуса.
- Мобильная адаптация (телефон — основной сценарий просмотра).
- Без авторизации, без личного кабинета — чисто читающая публичная страница.
- Не обязательно в v1, но заложить возможность на будущее: фильтр "показать
  только мою очередь" (по аналогии с тем, что уже есть в боте).

## Явно вне рамок (не делать)

- Парсинг исходного PDF — делается вручную отдельно.
- Полигоны зданий / закраска домов целиком (вместо точек) — не требуется,
  выбраны точки.
- Вся область, кроме Кременчука — следующий этап, после проверки на одном
  городе.
- Любые изменения в репозитории бота (`mazambik_parser_bot`) — отдельная
  сессия/проект, этот файл только описывает контракт (`status.json`), который
  бот должен будет реализовать со своей стороны.
